# PPT Markdown 双稿工作流

## 工作目标

把一次技术分享拆成两个职责清晰、逐页对应的 Markdown 文件：

- `PPT内容.md`：只写观众在页面上看到的内容；
- `PPT对应的演讲稿.md`：只写演讲者的逐页讲解、技术细节、边界和过渡。

让两份文件始终保持同一页数、同一页码、同一一级标题和同一叙事顺序。页面保持简洁，复杂解释放进讲稿，不要把讲稿压缩到页面上。

## 适用输入

处理以下输入：

- 用户已有的 PPT、历史分享、项目代码、设计文档、测试报告、标准文档和图片；
- 用户要求“先写 Markdown”“按页写 PPT 内容和演讲稿”“同步修改 PPT 和讲稿”或“梳理技术分享目录”；
- 用户逐页提出修改意见，需要同步更新页面正文和讲稿。

如果用户明确要求直接生成或编辑 PPTX，先用本工作流确定双稿，再按用户指定的 PPT 工具或模板继续制作。不要把 PPTX 生成规则混进本 Skill。

## 文件约定

默认输出目录为用户指定的 `outputs/ppt/`。用户没有指定时，在当前项目下创建 `outputs/ppt/`。

固定使用以下文件名：

- `PPT内容.md`
- `PPT对应的演讲稿.md`

每一页使用一个一级标题，格式固定为：

```markdown
# 第NN页｜页面标题
```

两份文件中的一级标题必须逐字一致。页面标题应表达这一页的结论或叙事作用，不要只写宽泛主题。

## 执行流程

### 1. 建立上下文

先读取用户提供的参考 PPT、已有 Markdown、项目目录和相关文档，确认：

- 受众、分享目标和预计技术深度；
- 用户希望保留的章节、页码、图片、代码和术语；
- 可公开展示的事实与需要抽象化的内部实现；
- 已存在的页面编号和标题，避免从中间页开始时破坏原有结构。

先给出简短目录和叙事主线。用户明确要求直接修改时，直接落盘，不要停在计划阶段。

### 2. 建立页面骨架

先在两份文件中建立完全相同的一级标题骨架，再分别填充正文和讲稿。让一个页面只承担一个主要叙事任务，并确保前一页提出的问题由后一页回答或推进。

优先考虑以下叙事顺序：

- 背景与问题；
- 关键概念或标准边界；
- 工程路径或架构；
- 代表性代码、测试或证据；
- 集成、缺陷闭环和结论。

### 3. 编写 `PPT内容.md`

按需使用以下页级结构：

```markdown
# 第NN页｜页面标题

## 页面标题

一句页面结论

## 关键内容

- 3～5条短句，使用书面化表达；
- 技术术语保持一致；
- 代码只保留能支撑当前结论的最小片段。

## 图片

![图片说明](/绝对路径/asset.png)

> 页面底部保留一句必要边界或结论。
```

遵守以下规则：

- 让页面文字服务于“看一眼就能复述的结论”，不要把演讲稿整段复制到页面；
- 复杂关系只在确实提升理解时使用一张图；简单流程使用 Mermaid，复杂关系图可使用 Graphviz；
- 本地图片使用绝对路径，并确认文件存在；图源和导出图片放在同一输出目录；
- 代码示例使用抽象名称、最小接口和必要注释，避免泄露真实项目细节；
- 用户要求“不要表格”时，改用代码块、流程、分层文字或简短结论；
- 不擅自删除用户要求保留的图片、章节或必要的标准说明。

### 4. 编写 `PPT对应的演讲稿.md`

让演讲稿一级标题与页面文件逐字一致。每页讲稿说明：

- 这一页要让听众理解什么；
- 页面元素之间的因果关系；
- 页面正文省略的技术背景、边界和例外；
- 与上一页、下一页的过渡；
- 事实依据、项目文件或外部资料来源。

每页优先写 2～6 段自然语言。不要写“这里放图”“此处动画”“模型提示”等制作过程语言。代码和图只在需要逐行解释时重复；通常解释其意图、输入、输出、假设和验证方式即可。

### 5. 逐轮修改

用户提出局部修改时，定位对应页并同步检查：

- 页面标题是否仍然准确；
- 页面中的代码、图片、图例和讲稿是否匹配；
- 前后页的术语、页码和叙事是否连贯；
- 是否应把新增细节放入讲稿而不是页面；
- 是否引入旧描述、过时数字或未验证结论。

不要只修改用户指出的一行就结束。对同一示例、同一章节或同一调用链涉及的前后页做一次关联检查。

## 一致性验证

完成编辑后运行：

```bash
python3 <skill-dir>/scripts/validate_md_pair.py \
  outputs/ppt/PPT内容.md \
  outputs/ppt/PPT对应的演讲稿.md
```

需要检查本地图片时增加 `--check-assets`：

```bash
python3 <skill-dir>/scripts/validate_md_pair.py \
  outputs/ppt/PPT内容.md \
  outputs/ppt/PPT对应的演讲稿.md \
  --check-assets
```

至少确认：

- 两个文件都存在且为 UTF-8；
- 一级标题数量相同；
- 页码、标题和顺序完全一致；
- 没有重复页码；
- 用户要求的图片和图源没有断链；
- 演讲稿没有残留旧页标题或与页面相反的结论。

## 交付检查

交付时报告：

- 两份 Markdown 的绝对路径；
- 总页数和标题同步验证结果；
- 图像或图表的生成与检查结果；
- 尚未完成的素材、事实核验或用户决策。

详细页级模板和修改检查清单见 [references/page-template.md](references/page-template.md)。
